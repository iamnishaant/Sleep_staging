# R2b run notes

## 2 Nov 2026: duplicate runners; first 11 arm C outputs discarded

- **What happened:** two copies of `run_r2b.py --go` ran at the same time.
  - PID 2604 was started at 10:23 from a background shell. The shell was reported dead, but the Python
    process survived and kept waiting for RAM.
  - PID 12876 was started at 10:43.
  - Both began generating once RAM was free (about 10:45).
- **Why it matters:** both runners wrote each night's prompt to the same file, `work/prompt_for_llm.txt`,
  just before launching the model. A generation could therefore have read another night's prompt and
  been saved under the wrong night. That would score as a false "wrong number" violation.
- **What was done:** all arm C outputs produced while both runners were active (13 by the time both were stopped) are
  discarded. They are moved to `discarded_duplicate_run/`, not deleted, and were never scored or read
  beyond counting them. They are regenerated by a single runner.
- **Pre-registration:** it forbids re-runs made because of a *result*. This is an infrastructure fault
  found before any arm C output was scored, so regenerating is consistent with it.
- **Fix:** the runner now takes a lock (`run.lock`), so a second copy refuses to start, and gives each
  run its own work folder (`work/<pid>/`).
